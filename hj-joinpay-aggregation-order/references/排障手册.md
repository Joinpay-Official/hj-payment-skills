# 排障手册

## 排障分流策略

```text
遇到错误
  │
  ├─ 有响应码(ra_Code/rb_Code)?
  │   │
  │   ├─ 是 → 查下方 TOP 20 速查表
  │   │       ├─ 匹配 → 按快速排查方向处理
  │   │       └─ 未匹配 → 加载 [响应码完整列表.md](../../hj-joinpay-aggregation-base/references/响应码完整列表.md)
  │   │
  │   └─ 否 → 进入路径B（异常诊断）
  │
  ▼
路径B: 异常诊断
  │
  ├─ 网络错误?
  │   └─ 检查base_url、DNS、防火墙、SSL证书
  │
  ├─ 超时?
  │   └─ 检查网络延迟、服务器负载、请求体大小
  │
  ├─ 解析失败?
  │   └─ 检查响应是否为有效JSON/form格式
  │
  └─ 以上都正常但仍异常?
      └─ 加载 [基础支付常见问题.md](./基础支付常见问题.md)
```

## 场景式排障

### 问题1：签名验证失败 (10080000)

这是**最常见**的错误，按以下步骤逐一排查：

1. **打印参与签名的参数列表**：确认哪些参数参与了签名
2. **检查排序结果**：正确排序应为 p0_Version, p1_MerchantNo, p2_OrderNo, p3_Amount ...
3. **手动复现拼接**：signStr = "2.6" + "商户号" + "订单号" + "0.01" + ... + "商品名称"
4. **常见坑点**：
   - ❌ 包含了 `hmac` 字段参与签名
   - ❌ 按 value 排序而非 key 排序
   - ❌ 拼接了 key=value 而不是只有 value
   - ❌ 忘记追加 merchantKey
   - ❌ 大小写不一致（应为 UPPER）
   - ❌ 编码问题（GBK vs UTF-8）

### 问题2：回调地址校验失败

汇聚服务端会在下单时**主动校验 p9_NotifyUrl 格式**，拒绝无法从公网访问的地址。

#### 被拒绝的地址类型

| 地址类型 | 示例 | 为什么被拒 |
|---------|------|-----------|
| `localhost` | `http://localhost:8080/notify` | localhost 指向的是汇聚服务器的本机 |
| `127.0.0.x` | `http://127.0.0.1:8080/notify` | 回环地址只有本机能访问 |
| 内网IP | `http://192.168.1.100:8080/notify` | 汇聚服务器在你的内网外 |
| 空值/非URL | `` 或 `abc` | 不是合法的 HTTP/HTTPS URL |

#### 解决方案

**方案1：使用内网穿透工具（推荐本地开发）**

```bash
# ngrok
ngrok http 8080
# 输出: https://xxxx.ngrok-free.app -> http://localhost:8080

# cpolar（国内速度更快）
cpolar http 8080
```

**方案2：使用测试服务器/生产环境域名**

```text
测试环境: http://10.x.x.x:8080/api/pay/notify
生产环境: https://pay.yourdomain.com/api/pay/notify
```

### 问题3：渠道下单失败 (10083001)

表示汇聚本身没问题，但**上游渠道**返回了错误：

1. 查看 `rb_CodeMsg` 中嵌套的渠道错误信息
2. 常见渠道级错误：
   - **微信**: appid未绑定 / openid无效 / 余额不足
   - **支付宝**: 协议已失效 / 买家账户受限
   - **银联**: 卡号无效 / 限额超限

### 问题4：商户未开通此支付方式 (10080012)

到汇聚后台申请开通对应的支付产品。

### 问题5：Appid未报备 (10080029)

AppId 需要在汇聚后台完成报备。
