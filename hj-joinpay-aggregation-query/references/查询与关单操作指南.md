# 查询与关单操作指南

## 订单查询最佳实践

### 轮询策略

下单后建议主动轮询查询订单状态，而非仅依赖前端回调：

```text
下单成功
    ↓
每 5~10 秒查询一次
    ↓
最多查询 30 次（约 5 分钟）
    ↓
仍为 NOTPAY → 调用关单接口
```

### 状态判断逻辑

```java
String code = response.getString("ra_Code");
String status = response.getString("ra_Status");

if ("100".equals(code) && "100".equals(status)) {
    // 支付成功
} else if ("101".equals(code)) {
    // 支付失败
} else {
    // 处理中，继续轮询
}
```

### 查询 vs 异步通知

| 维度 | 订单查询 | 异步通知 |
|------|---------|---------|
| 主动性 | 商户主动发起 | 汇聚主动推送 |
| 可靠性 | 取决于查询频率 | 取决于回调地址可达性 |
| 延迟 | 取决于轮询间隔 | 通常秒级 |
| 建议 | 作为主动确认手段 | 作为被动接收手段 |

**最佳实践**：两者结合使用。下单后轮询查询 + 接收异步通知，以异步通知为主、查询为辅。

## 关单操作指南

### 关单时机

1. 下单后超过 **30分钟** 仍未支付
2. 用户主动取消订单
3. 库存释放需要
4. 业务超时需要关闭

### 关单流程

```text
① 确认订单状态为 NOTPAY（先查询）
    ↓
② 调用关单接口
    ↓
③ 收到成功响应
    ↓
④ 更新本地订单状态为 CLOSED
    ↓
⑤ 释放库存等业务操作
```

### 关单常见错误

| 错误码 | 含义 | 解决方案 |
|--------|------|---------|
| 10080021 | 交易已关闭 | 无需重复关单 |
| 10083009 | 关单失败 | 检查订单状态是否为 NOTPAY |
