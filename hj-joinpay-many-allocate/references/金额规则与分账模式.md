# 金额规则与分账模式

多次分账的核心不是只会调接口，而是要先算清楚 `alt_this_amount`、手续费和分账净额关系。

## 核心概念

| 术语 | 符号 | 说明 |
|------|------|------|
| 订单金额 | `A` | 原支付总额 |
| 总手续费 | `F` | 原订单手续费 |
| 费率 | `p` | `F / A` |
| 本次总额 | `X` | `alt_this_amount` |
| 分账净额 | `Y` | `alt_amount` |
| 剩余可分金额 | `R_amt` | `A - ΣX` |
| 剩余在途金额 | `R_transit` | `(A - F) - ΣY` |

> 平台方（888）通常不出现在 `alt_info` 中；平台所得由系统按本次总额、手续费和分账方净额自动计算。

## 通用规则

- 所有金额字段按**字符串两位小数**处理。
- `alt_order_no` 每次唯一，不允许重复提交同一分账单号。
- 校验顺序至少包括：
  - `alt_this_amount <= 剩余可分金额`
  - `alt_amount <= 剩余在途金额`
- 异步通知必须做幂等，不能因为重复通知重复记账。

## 模式A：分账方承担手续费，平台不分账

### 计算

1. 本次手续费 `f = round(X * p, 2)`
2. 分账方净额 `Y = X - f`

### 适用场景

- 你只想把一部分金额分给分账方
- 平台不参与本次收益分配

### 例子

订单 `A=10.00`，手续费 `F=0.06`，费率 `p=0.006`。  
两次各分 `X=5.00`：

- 每次手续费 `f=0.03`
- 分账方到账 `Y=4.97`
- 平台保留 `0.03`

## 模式B：平台参与分账

### 计算

1. 本次手续费 `f = round(X * p, 2)`
2. 平台收入 `平台 = X - f - ΣY`

### 适用场景

- 同一笔划出金额里，平台和分账方都要分到钱
- 你已经明确分账方各自净额，剩余部分归平台

### 校验

- 平台收入不能小于 `0`
- `ΣY` 不能大于 `X - f`

## 模式C：指定分账方净额

### 计算

1. `X = round(Y / (1 - p), 2)`
2. `f = round(X * p, 2)`
3. `alt_amount = Y`

### 适用场景

- 业务方只关心“分账方实收多少”
- 你要反推本次应划出的总额 `alt_this_amount`

### 例子

目标净得 `Y=5.00`，费率 `p=0.006`：

- `X ≈ 5.03`
- `f ≈ 0.03`
- 分账方实收 `5.00`

## 边界处理

### 手续费为 0

当 `X * p < 0.005` 时，按当前四舍五入规则可能出现：

- `f = 0`
- `Y = X`

### 补扣机制

如果前几次分账由于金额过小导致手续费四舍五入为 `0`，最后一次可能补扣剩余手续费。

示例：

- 订单 `A=10.00`
- 总手续费 `F=0.06`
- 前两次 `X=0.50`，各次 `f=0`
- 第三次 `X=9.00`，补扣剩余 `0.06`
- 第三次净额 `Y=8.94`

### 最低手续费

文档补充规则指出：当订单金额乘费率后小于最小精度时，总手续费可能按最低 `0.01` 处理。实现时不要简单假设手续费一定等于“订单金额 × 费率”的理想值。

## 实现建议

- 金额计算使用十进制金额类型，不要直接用二进制浮点。
- 本地落库时同时保存：
  - 原订单金额
  - 订单总手续费
  - 每次 `alt_this_amount`
  - 每次 `alt_info[].alt_amount`
  - 剩余可分金额和剩余在途金额
- 完结分账前先做一次“全部分账汇总查询”，避免因为本地累计误差导致超限。
