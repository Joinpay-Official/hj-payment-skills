# 延迟分账与多次分账示例代码索引

这些示例演示 `/allocFunds` JSON 协议的关键动作：紧凑 JSON、`key=value&key=value` 待签名串、MD5/RSA 双签名，以及延迟分账/多次分账 V1.3.0 的 `altHandle.*` 接口。示例不包含真实商户资料、密钥或生产可直接提交的完整业务参数。

| 语言 | 示例文件 | 说明 |
|------|----------|------|
| Java | [ManyAllocateExample.java](Java/ManyAllocateExample.java) | JDK 标准库实现，适合 Java 8+ 改造 |
| PHP | [many_allocate_example.php](PHP/many_allocate_example.php) | 使用 cURL 和 OpenSSL 扩展 |
| Python | [many_allocate_example.py](Python/many_allocate_example.py) | 使用 `requests` 和 `cryptography` |
| Go | [many_allocate_example.go](Go/many_allocate_example.go) | 使用 Go 标准库 |

## 示例覆盖接口

| 接口 | method | 示例函数 | 说明 |
|------|--------|----------|------|
| 延迟分账请求 | `altHandle.singleLaterAllocate` | `singleLaterAllocate` / `single_later_allocate` | 演示原支付订单号、分账方明细和异步通知地址 |
| 延迟分账查询 | `altHandle.allocateQuery` | `queryDelayAllocate` / `query_delay_allocate` | 演示按 `alt_order_no` 查询单次延迟分账结果 |
| 多次分账请求 | `altHandle.manyLaterAllocate` | `manyLaterAllocate` / `many_later_allocate` | 演示原支付订单号、本次分账总额、营销分账金额、分账方明细和异步通知地址 |
| 完结分账 | `altHandle.finishAllocate` | `finishAllocate` / `finish_allocate` | 演示不再继续分账时，把订单剩余可分账金额归平台商户 |
| 查询单笔分账 | `altHandle.altManyOrderQuery` | `querySingleAllocate` / `query_single_allocate` | 演示按 `alt_order_no` 查询单笔分账结果 |
| 查询所有分账 | `altHandle.altManyTotalQuery` | `queryTotalAllocate` / `query_total_allocate` | 演示按 `mch_order_no` 查询支付订单维度的全部分账结果 |

## 使用前替换

| 占位符 | 说明 |
|--------|------|
| `YOUR_MERCHANT_NO` | 商户编号 `mch_no` |
| `YOUR_MERCHANT_KEY` | MD5 商户密钥，`sign_type=1` 时使用 |
| `MERCHANT_PRIVATE_KEY_PEM` | 商户 RSA 私钥，`sign_type=21` 时使用 |
| `YOUR_CALLBACK_URL` | 延迟分账、多次分账和完结分账异步通知地址，必须可直接访问且不要携带查询参数 |
| `PAID_ORDER_NO_PLACEHOLDER` | 已支付且支持延迟分账的原支付订单号 |
| `ALT_MCH_NO_PLACEHOLDER` | 已入网、启用并可分账的分账方编号 |
| `ALT_ORDER_NO_PLACEHOLDER` | 已提交过的分账订单号，用于单笔查询 |

## 注意

1. 示例默认使用 `sign_type=1` 的 MD5 签名；切换为 RSA 时将 `SIGN_TYPE/signType` 改为 `21`，并替换商户 RSA 私钥。
2. 签名时使用的 `data` JSON 字符串必须和实际发送的 `data` 完全一致，签名后不要重新格式化 JSON。
3. 文档 V1.3.0 要求金额字段使用字符串，示例统一写成 `"10.00"`、`"6.00"` 这种两位小数字符串。
4. `alt_order_no` 每次请求必须唯一，只能由英文字母、数字、下划线组成。
5. 同步返回 `resp_code=A1000` 只表示受理成功；最终分账结果以异步通知或查询接口为准。
6. 异步通知验签通过后，商户应返回 `{"resp_code":"A1000","resp_msg":"success"}`，并对通知做幂等处理。
