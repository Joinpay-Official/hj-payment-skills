# 错误码与排障

## 受理码

| 响应码 | 含义 |
|--------|------|
| `A1000` | 受理成功 |
| `A2000` | 受理失败 |
| `A3000` | 受理未知 |

## 常见业务码

| 业务码 | 含义 | 处理建议 |
|--------|------|---------|
| `B100000` | 成功 | 继续等异步通知或主动查询 |
| `B100001` | 验签失败 | 检查签名串顺序、`sign_type`、密钥与编码 |
| `B108006` | 分账总额不符 | 检查 `alt_this_amount` 与 `alt_info`、平台分账逻辑 |
| `B108022` | 分账金额超限 | 检查剩余可分金额、剩余在途金额 |
| `B1080311` | 分账方未升级 | 确认分账方资质或业务前提 |
| `B1080312` | 异主体比例超限 | 检查分账主体关系与比例约束 |

## 常见问题

### 1. 签名失败

优先检查：

- 是否按 ASCII 字典序排序外层参数
- 是否排除了 `sign`
- MD5 是否使用 `待签串&key=商户密钥`
- RSA 是否使用 `MD5withRSA`
- `sign_type` 是否与当前签名实现匹配：
  - `1` = MD5
  - `21` = RSA

### 2. 参数/JSON 错误

优先检查：

- `data` 是否为合法 JSON
- 金额字段是否用**字符串两位小数**
- `alt_order_no` 是否唯一
- `alt_info` 是否非空
- `callback_url` 是否完整可达

### 3. 金额超限

重点核对：

- `alt_this_amount <= 剩余可分金额`
- `alt_amount <= 剩余在途金额`
- 如果平台参与分账，平台剩余金额不能为负
- 小额多次分账是否触发了手续费补扣

### 4. 受理未知或回调未到

处理建议：

- 先按 `alt_order_no` 查询单笔分账
- 再按 `mch_order_no` 查询全部分账
- 不要因为同步超时就直接换新 `alt_order_no` 重提同一动作

### 5. 分账方状态异常

如果出现“分账方未升级”等错误：

- 先确认分账方是否满足平台侧业务前提
- 再确认是否是跨主体比例限制
- 必要时结合业务侧分账方资料、主体关系和客服反馈排查
