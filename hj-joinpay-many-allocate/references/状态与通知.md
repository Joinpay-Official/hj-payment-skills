# 状态与通知

多次分账的同步响应通常表示“已受理”，异步通知或主动查询才决定最终分账状态。

## 同步受理状态

| 字段 | 状态 | 含义 |
|------|------|------|
| `resp_code` | `A1000` | 受理成功 |
| `resp_code` | `A2000` | 受理失败 |
| `resp_code` | `A3000` | 受理未知 |
| `data.alt_main_status` | `P0001` | 处理中 |

## 异步通知

### 通知触发

- 多次分账成功后会异步回调商户 `callback_url`
- 完结分账也走异步回调确认
- 回调失败时会补发 4 次，间隔通常为：
  - `5` 秒
  - `20` 秒
  - `60` 秒
  - `120` 秒

### 通知关键字段

| 字段 | 说明 |
|------|------|
| `mch_order_no` | 原支付订单号 |
| `alt_order_no` | 分账订单号 |
| `alt_this_amount` | 本次分账总额 |
| `alt_main_status` | 主状态；成功常见 `P1000` |
| `alt_info` | 分账方明细，含分账流水号和分账状态 |

### alt_info 明细状态

| 状态 | 含义 |
|------|------|
| `100` | 成功 |
| `101` | 失败 |
| `102` | 已创建 |

## 商户确认返回

文档给出的成功确认示例：

```json
{"resp_code":"A1000","resp_msg":"success"}
```

如果你的本地系统还没可靠落库，不要提前回成功，否则平台可能停止补发。

## 幂等建议

推荐幂等 key：

```text
alt_order_no + alt_main_status
```

如果需要更细粒度，可再拼接：

- `mch_order_no`
- `alt_info[].alt_mch_no`
- `alt_info[].status`

## 状态更新原则

- 已成功的分账单，不允许被旧通知覆盖回处理中或失败。
- 同一状态的重复通知直接幂等返回成功。
- `A3000` 或网络超时场景，不要凭同步响应直接判失败，应主动查询。
- 完结分账和多次分账属于不同业务动作，`alt_order_no` 不要复用。

## 推荐落库字段

| 字段 | 用途 |
|------|------|
| `mch_order_no` | 原支付订单号 |
| `alt_order_no` | 分账订单号 |
| `alt_main_status` | 本次分账主状态 |
| `alt_this_amount` | 本次分账总额 |
| `alt_detail_info` | 分账方明细、流水号和状态 |
| `callback_raw` | 脱敏后的回调原文 |
| `last_notify_time` | 最近通知时间 |
| `notify_count` | 通知处理次数 |
