# 延迟分账操作指南

本指南适用于《汇聚延迟分账 API 接口文档 V1.3.0》。延迟分账使用 `/allocFunds` JSON 协议，通过 `altHandle.*` method 分发，签名规则与多次分账一致。

## 接口列表

| 接口 | method | 用途 | 版本 |
|------|--------|------|------|
| 延迟分账请求 | `altHandle.singleLaterAllocate` | 对已支付且支持延迟分账的订单发起一次分账 | `1.1` |
| 查询接口 | `altHandle.allocateQuery` | 根据分账订单号查询延迟分账结果 | `1.1` |

## 公共请求参数

| 参数 | 必填 | 参与签名 | 说明 |
|------|------|----------|------|
| `method` | 是 | 是 | 固定为接口 method |
| `version` | 是 | 是 | 固定为 `1.1` |
| `data` | 是 | 是 | HTTP 请求中为业务 JSON 对象；签名时使用该对象的紧凑 JSON 字符串 |
| `rand_str` | 是 | 是 | 32 位随机字符串 |
| `sign_type` | 是 | 是 | `1`=MD5，`21`=RSA |
| `mch_no` | 是 | 是 | 商户编号 |
| `sign` | 是 | 否 | 请求签名 |

## 延迟分账请求

### data 参数

| 参数 | 必填 | 参与签名 | 说明 |
|------|------|----------|------|
| `mch_order_no` | 是 | 是 | 分账前已支付的商户订单号 |
| `alt_order_no` | 是 | 是 | 分账请求唯一标识，只能由英文字母、数字、下划线组成 |
| `alt_info` | 是 | 是 | 分账方数组 |
| `callback_url` | 是 | 是 | 可直接访问的异步通知 URL，不可携带参数 |

### alt_info 参数

| 参数 | 必填 | 参与签名 | 说明 |
|------|------|----------|------|
| `alt_mch_no` | 是 | 是 | 分账方编号 |
| `alt_amount` | 是 | 是 | 分账金额，单位元，如 `29.99` |

## 查询接口

### data 参数

| 参数 | 必填 | 参与签名 | 说明 |
|------|------|----------|------|
| `alt_order_no` | 是 | 是 | 分账订单号 |

## 响应与状态

| 字段 | 说明 |
|------|------|
| `resp_code` | 受理响应码；`A1000` 表示受理成功，最终结果仍以异步通知或查询为准 |
| `data.alt_main_status` | 分账主状态；`P0001`=处理中，`P1000`=分账成功 |
| `data.biz_code` | 业务响应码；`B100000` 常见为受理成功 |
| `data.alt_info[].alt_status` | 分账明细状态；`100`=成功，`101`=失败，`102`=已创建 |

## 异步通知

延迟分账成功后，汇聚通过 `callback_url` POST 通知商户。商户验签通过并处理成功后返回：

```json
{"resp_code":"A1000","resp_msg":"success"}
```

`success` 必须小写，且不要追加其他字符。通知处理必须做幂等，避免重复通知导致重复入账或终态被旧状态覆盖。

## 注意事项

1. 参数值不要包含 `0x0d`、`0x0a`、`0x4f`、`=`、`|`、`%`、`<`、`+`、`¥`、`$`、`\r\n` 等特殊符号。
2. HTTP 请求体中的 `data` 必须是 JSON 对象。签名时单独生成该对象的紧凑 JSON 字符串；请求发送时仍使用原对象，不能把签名用字符串放入 `data`。
3. 金额字段按字符串处理，建议统一保留两位小数。
4. RSA 签名方式使用 `sign_type=21`，算法为 `MD5withRSA`。
5. 查询接口按 `alt_order_no` 查询，不按支付订单号查询。
