# 错误处理矩阵

本矩阵用于统一错误归因和处理策略。默认原则：先保证本地订单或申请单状态正确；处理中优先查询确认，配置和签名类错误不要盲目重试。

## 通用错误处理

| 错误层级 | 典型表现 | 是否重试 | 是否查单/查询申请单 | 是否落库 | 是否告警 | 用户侧提示 |
|----------|----------|----------|---------------------|----------|----------|------------|
| 网络/HTTP 超时 | 连接失败、读超时、HTTP 5xx、无响应 | 可按退避策略重试，避免无限重试 | 聚合支付下单后如订单号可能已送达应先查单；二级商户创建后用业务单号查询；多次分账优先按 `alt_order_no` 查询 | 记录请求中或未知状态 | 连续失败需告警 | 系统处理中，请稍后查询结果 |
| 签名/验签失败 | `10080000`、`10080002`、响应或回调验签失败 | 不重试 | 不需要，先修签名配置 | 记录失败原因，敏感信息脱敏 | 需要告警 | 配置异常，请联系技术支持 |
| 参数校验失败 | 必填缺失、版本错误、FrpCode 错误、JSON 解析错误 | 不重试 | 不需要 | 记录参数校验失败 | 视频率告警 | 请求参数有误，请修正后重试 |
| 渠道处理中 | `10083002`、退款 `102`、渠道返回处理中 | 不立即重复提交 | 必须按订单号或退款单号查询 | 记录处理中状态 | 超过 SLA 告警 | 交易处理中，请稍后刷新 |
| 业务失败 | 支付失败、退款失败、二级商户审核拒绝、签约失败、多次分账业务失败 | 修正原因后再发起新动作 | 可查询确认最终状态 | 记录终态和失败原因 | 重要业务失败告警 | 展示可理解的失败原因 |
| 重复请求 | 订单号重复、重复退款、重复通知 | 不重试同一请求 | 查询原请求结果 | 幂等返回已有结果 | 异常频率告警 | 请勿重复提交，已返回原处理结果 |
| 本地状态冲突 | 已支付再关单、已退款重复退款、回调乱序 | 不重试原动作 | 必须查单或按状态机核验 | 保留当前可信终态 | 状态冲突需告警 | 当前状态不允许该操作 |

## 聚合支付重点

| 场景 | 推荐处理 |
|------|----------|
| 下单超时 | 使用 `p2_OrderNo` 调用订单查询；查到成功则更新支付成功，查到未支付则保持待支付或继续轮询 |
| 签名失败 | 检查是否排除 `hmac`、是否只拼 value、密钥是否正确、编码是否 UTF-8；见 [签名硬约束](signing-constraints.md) |
| 渠道下单失败 | 查看 `rb_CodeMsg` 的上游渠道错误，判断是否需用户换卡/换渠道/修商户配置 |
| 退款处理中 | 按退款单号调用 `queryRefund`，不要重复使用新退款单号发起同一笔退款 |
| 关单失败 | 先查询原订单状态；已支付只能退款，已关闭不用重复关单 |

聚合支付错误码参考 [响应码完整列表](../../hj-joinpay-aggregation-base/references/响应码完整列表.md) 和 [排障手册](../../hj-joinpay-aggregation-order/references/排障手册.md)。

## 二级商户重点

| 场景 | 推荐处理 |
|------|----------|
| 创建或升级超时 | 使用 `mch_order_no` 或平台返回流水查询申请单，不要直接换单号重复提交相同资料 |
| 网关验签失败 | 检查是否误用聚合支付 `hmac`，确认 `data` 是最终紧凑 JSON 原文，`sign/sec_key` 未参与签名 |
| `sec_key` 解密失败 | 检查 AES key、平台公钥、RSA 填充和敏感字段是否重复加密 |
| 审核拒绝 | 保存拒绝原因，按文档修改资料后调用修改或重新提交 |
| 回调重复或乱序 | 按 `mch_order_no/trx_no/status` 幂等处理，终态不得被旧状态覆盖 |

二级商户状态和通知参考 [状态与通知](../../hj-joinpay-secondary-mch/references/状态与通知.md)。

## 多次分账重点

| 场景 | 推荐处理 |
|------|----------|
| 受理未知 `A3000` | 先用 `alt_order_no` 查询单笔分账，再按 `mch_order_no` 查询全部分账，不要直接换单号重提 |
| 签名失败 | 检查是否误用了聚合支付只拼 value 或二级商户 `sec_key` 规则，确认 `sign_type` 为 `1` 或 `21` |
| 分账总额不符 | 核对 `alt_this_amount`、`alt_info`、平台分账额和手续费计算 |
| 分账金额超限 | 核对剩余可分金额、剩余在途金额和补扣手续费逻辑 |
| 回调重复或乱序 | 按 `alt_order_no + alt_main_status` 幂等处理，成功终态不回滚 |

多次分账错误码参考 [错误码与排障](../../hj-joinpay-many-allocate/references/错误码与排障.md)。
