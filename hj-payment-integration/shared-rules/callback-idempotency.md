# 回调与幂等

本规则用于支付、退款、二级商户通知的统一处理。回调只表示平台主动通知，不应替代查询接口；最终状态以验签通过后的通知、主动查询和本地状态机共同确认。

## 统一处理顺序

```text
接收回调
  -> 验签
  -> 解析业务字段
  -> 幂等判断
  -> 必要时主动查询核验
  -> 按状态机更新本地记录
  -> 返回 success
```

验签失败返回 `fail` 或错误响应，不更新业务状态，不打印敏感字段明文。

## 幂等 key

| 通知类型 | 默认幂等 key | 状态更新原则 |
|----------|--------------|--------------|
| 聚合支付支付通知 | `p2_OrderNo` + 通知类型 + 最终状态 | 已成功的订单不得被失败或处理中覆盖；未知状态先查询 |
| 聚合支付退款通知 | 退款单号 + 退款状态 | 同一退款单号只更新一次终态；处理中可被成功或失败覆盖 |
| 二级商户申请单通知 | `mch_order_no/trx_no/status` | 同一状态重复通知直接返回成功；终态不得被旧状态覆盖 |
| 二级商户签约通知 | `mch_order_no/trx_no/status` 或签约单号 + 状态 | 签约成功、撤销成功等终态按状态机处理 |
| 分账方入网与结算通知 | 分账方通知用 `alt_mch_no/login_name + 状态`；结算通知用 `mch_order_no + order_status` | 认证、签约、结算成功不得被旧状态覆盖；图片审核通过通常无通知 |
| 多次分账通知 | `alt_order_no` + `alt_main_status` | 已成功的分账单不得被旧通知覆盖；同步未知场景先查询单笔或全部分账 |

## 响应规则

| 场景 | 响应 |
|------|------|
| 验签失败 | `fail`，并记录脱敏日志 |
| 幂等重复且已处理成功 | `success` |
| 业务处理成功 | `success` |
| 本地数据库短暂异常 | `fail`，允许平台补发 |
| 业务字段不完整 | `fail`，记录错误并告警 |

返回 `success` 后通常表示平台停止补发，因此只有在本地状态已经可靠落库后才能返回。

## 聚合支付回调

| 要点 | 规则 |
|------|------|
| 验签 | 使用聚合支付 `hmac` 规则，排除 `hmac`，按 key 排序后只拼 value |
| 支付成功 | 先按订单号锁定本地订单，再校验金额、商户号、订单号，最后更新成功 |
| 支付失败 | 记录失败原因；如果本地已成功，不覆盖成功状态 |
| 退款通知 | 按退款单号幂等；退款处理中不视为终态 |
| 主动查询 | 对状态冲突、金额不一致、处理中超时的订单主动调用查询接口 |

聚合支付异步通知规则见 [async-notify.md](../../hj-joinpay-pay-shared-base/protocol/async-notify.md)。

## 二级商户回调

| 要点 | 规则 |
|------|------|
| 验签 | 使用 API Gateway JSON 响应/回调验签规则，排除 `sign/sec_key`，按 key 排序拼 `key=value` |
| 解密 | 如含敏感字段，先用商户私钥解密 `sec_key`，再用 AES 解密 `data` 内敏感字段 |
| 申请单 | 按 `mch_order_no` 和平台流水保存审核状态，重复通知直接幂等成功 |
| 签约 | 按签约单号或 `trx_no` 保存签约状态，撤销和签约成功均作为终态处理 |
| 打款认证 | 打款认证失败后按文档修改结算账户资料，不要重复创建新商户 |

二级商户状态说明见 [状态与通知](../../hj-joinpay-secondary-mch/references/状态与通知.md)。

## 分账方入网与结算回调

| 要点 | 规则 |
|------|------|
| 验签 | 使用分账方 `/allocFunds` 规则，排除 `sign` 和可能存在的 `aes_key`，按 key 排序拼 `key=value` |
| 打款认证 | 按 `alt_mch_no/login_name + auth_status` 幂等；认证成功不得被旧的认证中覆盖 |
| 图片审核 | 图片审核不通过才回调，通过通常无通知；必要时主动查询图片状态 |
| 页面签约 | 按分账方编号和签约状态幂等；签约成功作为终态处理 |
| 手工结算 | 按 `mch_order_no + order_status` 幂等；同步未知或处理中先调用结算查询 |
| 应答 | 本地可靠落库后再返回文档要求的成功确认格式 |

分账方状态说明见 [状态与通知](../../hj-joinpay-alt-mch-settlement/references/状态与通知.md)。

## 多次分账回调

| 要点 | 规则 |
|------|------|
| 验签 | 使用多次分账 `/allocFunds` 规则，排除 `sign`，按 key 排序拼 `key=value` |
| 主状态 | 同步受理成功后常见 `P0001`；异步成功常见 `P1000` |
| 明细状态 | `alt_info` 中 `100`=成功、`101`=失败、`102`=已创建 |
| 幂等 | 按 `alt_order_no + alt_main_status` 去重；已成功终态不得被旧状态覆盖 |
| 查询 | 同步超时、`A3000`、回调未达时，先查单笔分账，再查订单全部分账 |
| 应答 | 本地可靠落库后再返回文档要求的成功确认格式 |

多次分账状态说明见 [状态与通知](../../hj-joinpay-many-allocate/references/状态与通知.md)。
