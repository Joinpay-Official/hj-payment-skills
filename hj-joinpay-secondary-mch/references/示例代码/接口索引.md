# 二级商户示例代码索引

这些示例只演示 API Gateway JSON 协议的关键动作：敏感字段 AES 加密、紧凑 JSON、`key=value&key=value` 待签名串、RSA 签名、平台公钥加密 `sec_key`。示例不包含真实商户资料、密钥或内网地址。

| 语言 | 示例文件 | 说明 |
|------|----------|------|
| Java | [SecondaryMchCreateExample.java](Java/SecondaryMchCreateExample.java) | JDK 标准库实现，适合 Java 8+ 改造 |
| PHP | [secondary_mch_create_example.php](PHP/secondary_mch_create_example.php) | 使用 OpenSSL 扩展 |
| Python | [secondary_mch_create_example.py](Python/secondary_mch_create_example.py) | 使用 `cryptography` 包 |
| Go | [secondary_mch_create_example.go](Go/secondary_mch_create_example.go) | 使用 Go 标准库 |

## 使用前替换

| 占位符 | 说明 |
|--------|------|
| `YOUR_MERCHANT_NO` | 平台商户号 |
| `YOUR_CALLBACK_URL` | 异步通知地址 |
| `MERCHANT_PRIVATE_KEY_PEM` | 商户 RSA 私钥，请求签名用 |
| `PLATFORM_PUBLIC_KEY_PEM` | 汇聚平台 RSA 公钥，`sec_key` 加密和响应验签用 |
| `IMAGE_ID_*` | 通过 `secondaryMchPics.uploadPic` 获取的资质图片 ID |

## 注意

1. 示例使用 `secondaryMch.create`。改为 `secondaryMch.upgrade`、`secondaryMch.modify` 等接口时，必须同步调整 `method` 和 `data` 字段结构。
2. `data` 一旦序列化并参与签名，请求发送时必须使用同一个字符串。
3. AES 模式按现有二级商户脚本口径使用 AES-128-ECB + PKCS#5/PKCS#7 padding。
