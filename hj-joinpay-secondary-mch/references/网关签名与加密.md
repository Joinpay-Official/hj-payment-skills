# 网关签名与加密

本规则仅适用于二级商户 API Gateway JSON 协议，不适用于聚合支付 `/tradeRt/*`。

## 协议对比

| 项目 | 二级商户入网 | 聚合支付 |
|------|--------------|----------|
| 请求路径 | `/altFunds` | `/tradeRt/*` |
| 公共参数 | `method/version/data/rand_str/sign_type/mch_no/sign/sec_key` | `p0_/p1_/q*/交易签名字段` |
| 签名字段 | `sign` | 聚合支付交易签名字段 |
| 待签名串 | `key=value&key=value` | 按 key 排序后只拼 value |
| 请求格式 | JSON body，`data` 是 JSON 字符串 | form-urlencoded |
| 敏感字段 | AES 加密，AES key 放入 `sec_key` | 通常不使用 `sec_key` |

## 签名硬约束

1. `sign` 和 `sec_key` 不参与签名。
2. 参与签名字段按字段名升序排列，格式为 `key=value`，字段间用 `&` 连接。
3. `data` 的值必须是最终上送的紧凑 JSON 字符串；签名后不得重新序列化。
4. `sign_type=2` 使用 RSA 签名，算法沿服务端实现为 `MD5withRSA`。
5. 请求签名使用商户私钥；响应和回调验签使用平台公钥。

示例签名串：

```text
data={"mch_order_no":"ORDER202605070001","mch_info":{"login_name":"demo_user"}}&mch_no=888000000000000&method=secondaryMch.create&rand_str=0123456789abcdef0123456789abcdef&sign_type=2&version=1.0
```

## 敏感字段加密流程

```text
生成 16 位 AES key
  ↓
对 data 内敏感字段逐个 AES 加密
  ↓
把加密后的 data 序列化为紧凑 JSON 字符串
  ↓
用该 JSON 字符串参与签名
  ↓
用平台公钥 RSA 加密 AES key，得到 sec_key
  ↓
发送 JSON body
```

## Python 伪代码

```python
import json

def build_request(data_map, merchant_no, merchant_private_key, platform_public_key):
    aes_key = random_16_chars()

    encrypt_sensitive_fields_in_place(data_map, aes_key)
    data_json = json.dumps(data_map, separators=(",", ":"), ensure_ascii=False)

    params_for_sign = {
        "data": data_json,
        "mch_no": merchant_no,
        "method": "secondaryMch.create",
        "rand_str": random_32_chars(),
        "sign_type": "2",
        "version": "1.0",
    }

    sign_str = "&".join(f"{k}={params_for_sign[k]}" for k in sorted(params_for_sign))
    sign = rsa_sign_md5withrsa(sign_str, merchant_private_key)
    sec_key = rsa_encrypt(aes_key, platform_public_key)

    return {
        **params_for_sign,
        "sign": sign,
        "sec_key": sec_key,
    }
```

## Java 伪代码

```java
Map<String, Object> dataMap = buildDataMap();
String aesKey = random16();
encryptSensitiveFields(dataMap, aesKey);

String dataJson = objectMapper.writeValueAsString(dataMap); // 禁止 pretty print

Map<String, String> signMap = new TreeMap<>();
signMap.put("data", dataJson);
signMap.put("mch_no", merchantNo);
signMap.put("method", "secondaryMch.create");
signMap.put("rand_str", random32());
signMap.put("sign_type", "2");
signMap.put("version", "1.0");

String signStr = signMap.entrySet().stream()
        .map(e -> e.getKey() + "=" + e.getValue())
        .collect(Collectors.joining("&"));

String sign = rsaSignMd5WithRsa(signStr, merchantPrivateKey);
String secKey = rsaEncryptByPublicKey(aesKey, platformPublicKey);

Map<String, String> requestBody = new LinkedHashMap<>(signMap);
requestBody.put("sign", sign);
requestBody.put("sec_key", secKey);
```

## 响应与回调验签

响应和回调也使用同一类公共结构：`biz_code/biz_msg/data/rand_str/sign_type/mch_no/sign/sec_key`。验签时同样排除 `sign` 和 `sec_key`，按 key 排序拼接 `key=value`。

如果响应包含加密敏感字段，先使用商户私钥解密响应 `sec_key` 得到 AES key，再解密 `data` 内对应字段。
