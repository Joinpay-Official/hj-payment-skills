# 二级商户接口总览

二级商户入网使用 API Gateway JSON 协议，统一入口为 `/altFunds`。生产地址为 `https://api.joinpay.com/altFunds`，测试地址按接入方环境配置，不在 Skill 中硬编码内网地址。

## 公共请求

| 参数 | 说明 |
|------|------|
| `method` | 接口方法名，如 `secondaryMch.create` |
| `version` | 接口版本，常用 `1.0`；部分查询/签约接口可按文档支持 `1.1`、`1.2` |
| `data` | 业务参数 JSON 字符串 |
| `rand_str` | 32 位随机字符串 |
| `sign_type` | RSA 为 `2` |
| `mch_no` | 平台商户号 |
| `sign` | 请求签名 |
| `sec_key` | 平台公钥加密后的 16 位 AES key；无敏感字段时可为空，二级商户资料接口通常需要 |

## 接口列表

| 接口 | method | 用途 | 同步响应重点 | 异步通知 |
|------|--------|------|--------------|----------|
| 二级商户添加 | `secondaryMch.create` | 新商户入网，创建申请单 | `mch_order_no`、`trx_no` | 审核通过/驳回、待签约、激活、冻结 |
| 二级商户添加（存量） | `secondaryMch.upgrade` | 已有分账方升级二级商户 | `mch_order_no`、`trx_no` | 审核通过/驳回、待签约、激活、冻结 |
| 二级商户修改 | `secondaryMch.modify` | 修改二级商户资料、结算卡等 | `alt_mch_no`、`mch_status` | 修改结果、状态变化 |
| 二级商户查询 | `secondaryMch.query` | 按申请单或二级商户号查询状态 | 申请单、商户、签约、法人、结算账户信息 | 无 |
| 图片上传 | `secondaryMchPics.uploadPic` | 上传资质图片并换取 `image_id` | `image_id` | 无 |
| 发起签约 | `secondaryMchSign.create` | 发起二级商户电子签约 | 签约状态、签约链接、签署人信息 | 签约流程完成 |
| 签约撤销 | `secondaryMchSign.revoke` | 撤销签约订单 | 撤销结果 | 无 |
| 签约查询 | `secondaryMchSign.query` | 查询签约订单状态 | 签约状态、签约链接、签署人信息 | 无 |

> 补充资料中可能出现 `altMchPics.uploadPic` 的旧称或泛称；二级商户入网 API 文档中的正式 method 使用 `secondaryMchPics.uploadPic`。

## 业务流程

```text
上传图片换取 image_id
  ↓
secondaryMch.create 或 secondaryMch.upgrade 创建入网申请单
  ↓
申请单 P1000 已创建
  ↓
汇聚系统机审
  ↓
场景材料人工审核
  ↓
审核通过后生成或绑定二级商户
  ↓
自动发起签约；必要时可撤销后手动重签
  ↓
二级商户法人或签署人完成签约
  ↓
新商户自动发起 0.01 元打款认证
  ↓
认证成功激活；认证失败冻结，可通过 modify 修改结算卡
  ↓
商户可正常入账、出款和结算
```

## 新增与存量差异

| 场景 | 推荐接口 | 打款认证 |
|------|----------|----------|
| 新商户第一次入网 | `secondaryMch.create` | 会发起 |
| 已有分账方升级为二级商户 | `secondaryMch.upgrade` | 不会再次发起 |

## 自动签约与手动重签

审核通过后系统会自动向法人或入网时指定的签署人发送签约短信或 H5 链接。签署人信息错误、手机号错误或需要更换签署人时，按以下顺序处理：

```text
secondaryMchSign.revoke 撤销原待签署合同
  ↓
secondaryMchSign.create 重新发起签约并传入正确签署人信息
  ↓
引导商户使用新的 sign_url 或小程序签署参数完成签署
```

撤销前提是商户仍处于待签约，且合同仍是待签署状态。系统自动发起的合同撤销时，通常使用入网时的 `mch_order_no`；手动发起的合同撤销时，使用签约接口传入的签约订单号。

## 可结算前提

商户可正常结算前需同时满足：

| 前提 | 目标状态 |
|------|----------|
| 商户状态 | `P2000` 已激活 |
| 签约状态 | `P3000` 已生效 |
| 账户验证 | 0.01 元打款认证成功 |

补充流程资料强调：商户状态变为已激活前，不能入账，也不能出款。实现时应以“已激活 + 签约已生效 + 账户验证成功”作为可结算判断。

## 结算参数口径

| 字段 | 常见值 | 说明 |
|------|--------|------|
| `sett_mode` | `1` 自动结算、`2` 手工结算、`3` 手工+D0、`4` 自动+D0 | 入网时选择 |
| `sett_date_type` | `1` 工作日、`2` 自然日、`3` 月结日 | 与 `risk_day` 配合 |
| `risk_day` | `1` 表示 T+1/D+1；月结时表示每月几号 | 按结算周期解释 |

打款认证失败时，可通过 `secondaryMch.modify` 修改 `account_info`，修改结算账户会重新触发打款认证；认证成功后商户自动恢复为已激活。
