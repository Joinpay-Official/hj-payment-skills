# 退款操作指南

## 退款流程

```text
① 确认原订单状态为 SUCCESS（已支付）
    ↓
② 计算退款金额（≤ 剩余可退金额）
    ↓
③ 生成唯一的退款订单号
    ↓
④ 调用退款接口
    ↓
⑤ 处理退款响应
    │
    ├─ ra_Status=100 → 退款成功
    ├─ ra_Status=102 → 退款处理中，后续查询确认
    └─ ra_Status=101 → 退款失败，查看 rb_Code
```

## 部分退款示例

```text
原订单: 100.00 元

退款1: 30.00 → REF_001 → 成功 → 剩余可退 70.00
退款2: 50.00 → REF_002 → 成功 → 剩余可退 20.00
退款3: 20.00 → REF_003 → 成功 → 剩余可退 0.00（全额已退完）
退款4: 10.00 → REF_004 → 失败(20090004) → 退款金额超出可退金额
```

## 退款订单号生成建议

```text
方案1: REF_{原订单号}_{时间戳}
  示例: REF_ORDER20260413001_20260418120000

方案2: RF{yyyyMMddHHmmssSSS}{6位随机数}
  示例: RF20260418120000123456789

规则:
- 全局唯一
- 仅英文、数字、下划线
- 最长50字符
- 不可与已有支付订单号或退款订单号重复
```

## 退款状态判断

```java
String status = response.getString("ra_Status");
String code = response.getString("rb_Code");

if ("100".equals(status)) {
    // 退款成功 ✅
} else if ("102".equals(status)) {
    // 退款处理中 🔄 — 稍后查询确认
} else if ("101".equals(status)) {
    // 退款失败 ❌ — code 为具体错误码
    switch (code) {
        case "20090001": // 支付成功记录不存在
        case "20090012": // 退款订单号已存在
        case "20090020": // 剩余可退金额不足
        case "20090023": // 可用余额不足
    }
}
```

## 退款查询策略

| 场景 | 推荐接口 | 说明 |
|------|---------|------|
| 追踪单笔退款 | queryRefund | 输入退款订单号 |
| 对账检查 | queryRefundInfo | 输入原支付订单号，返回所有退款记录 |

## 分账退款

如果原订单使用了分账功能：

```json
{
  "altRefList": [
    {
      "receiverAccount": "分账接收方账号",
      "refundAmount": "10.00",
      "description": "商品退款"
    }
  ]
}
```

> **注意**：分账退款金额不能超过该接收方的实际分账金额。超出返回 `20090021`。
