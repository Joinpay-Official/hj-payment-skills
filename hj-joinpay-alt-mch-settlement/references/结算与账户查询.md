# 结算与账户查询

分账方结算接口使用 `/allocFunds` JSON 协议。手工结算为后台调用加异步通知，查询接口用于主动确认结果或补偿异步通知缺失。

## 手工结算

| 项 | 内容 |
|----|------|
| method | `altSettle.launch` |
| version | `1.1` |
| 交互模式 | 后台调用 + 异步通知 |
| 请求入口 | `https://www.joinpay.com/allocFunds` |

### data 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `alt_mch_no` | 是 | 分账方编号 |
| `product_code` | 否 | 产品类型：`2`=余额结算，`3`=D0 结算 |
| `settle_amount` | 是 | 结算金额，单位元，两位小数 |
| `settle_fee` | 否 | 平台服务费，不超过结算金额 1% |
| `mch_order_no` | 是 | 结算订单号，16-32 位字母、数字、下划线 |
| `special_mch` | 否 | 是否特约商户：`1`=是 |
| `callback_url` | 是 | 结算结果异步通知地址，HTTP 或 HTTPS |

同步响应包含 `resp_code`、`resp_msg`、`data`、`rand_str`、`sign_type`、`mch_no`、`sign`。同步 `A1000` 只表示受理成功，最终结算结果以异步通知或查询为准。

## 结算查询

| 项 | 内容 |
|----|------|
| method | `altSettle.get` |
| 用途 | 查询手工结算结果 |
| 核心参数 | `mch_order_no` |

建议在以下场景主动查询：

- 发起结算后异步通知未到
- 同步响应为 `A3000`
- 网络超时或调用方不确定请求是否被受理
- 本地状态与异步通知状态冲突

## 自动结算查询

| 项 | 内容 |
|----|------|
| method | `altSettle.getAutoSettle` |
| 用途 | 查询自动结算记录 |
| 核心参数 | `settle_date`、`alt_mch_no` |

`settle_date` 按接入文档要求传入结算日期。调用前应确认分账方 `sett_mode` 支持自动结算或自动+D0。

## 账户余额查询

| 项 | 内容 |
|----|------|
| method | `altAccount.get` |
| 用途 | 查询分账方账户余额 |
| 核心参数 | `alt_mch_no` |

返回信息重点关注：

| 字段类别 | 说明 |
|----------|------|
| 担保余额 | 分账方担保交易相关余额 |
| 当日收款 | 分账方当日收款金额 |
| 可结算余额 | 可用于发起结算的余额 |
| 总余额 | 分账方账户总余额 |

## 金额处理规则

| 项 | 规则 |
|----|------|
| 金额格式 | 字符串，两位小数 |
| 精度处理 | 使用 Decimal/BigDecimal，不使用浮点累加 |
| `settle_fee` | 不超过 `settle_amount` 的 1% |
| 余额不足 | 不应重试同一参数，应先查账户余额和结算冻结状态 |

## 结算前置条件

发起结算前确认：

1. 分账方认证成功
2. 资质图片已上传并审核通过
3. 协议签约完成
4. 可结算余额足够
5. `mch_order_no` 全局唯一且未被使用
