# 状态与通知

分账方入网、图片审核、签约和结算都可能涉及异步通知。通知必须验签、幂等处理，并在本地可靠落库后再返回成功确认。

## 认证状态

| 字段 | 状态 | 含义 |
|------|------|------|
| `auth_status` | `R4001` | 未认证 |
| `auth_status` | `R4002` | 认证中 |
| `auth_status` | `R4003` | 认证失败 |
| `auth_status` | `R4004` | 认证成功 |

打款认证失败后，应按可修改规则调整结算账户资料，不要盲目重复创建分账方。

## 审批状态

| 字段 | 状态 | 含义 |
|------|------|------|
| `approve_status` | `P0001` | 未审批 |
| `approve_status` | `P1000` | 审批通过 |
| `approve_status` | `P2000` | 审批不通过 |

图片审核通过通常无通知，审核不通过才异步通知。因此接入方需要通过查询接口或本地状态推进确认审核结果。

## 结算状态

| 字段 | 状态 | 含义 |
|------|------|------|
| `resp_code` | `A1000` | 受理成功 |
| `resp_code` | `A2000` | 受理失败 |
| `resp_code` | `A3000` | 受理未知 |
| `order_status` | `P1000` | 交易成功 |
| `order_status` | `P2000` | 交易失败 |
| `order_status` | `P3001` | 处理中 |

同步受理成功不代表结算最终成功。`A3000`、网络超时或通知缺失时，优先调用 `altSettle.get` 或 `altSettle.getAutoSettle` 主动查询。

## 异步通知重试

结算完成后汇聚会 POST 回调 `callback_url`。回调失败会补发 4 次，常见间隔为：

- 5 秒
- 20 秒
- 60 秒
- 120 秒

商户处理成功后返回：

```json
{"resp_code":"A1000","resp_msg":"success"}
```

## 通知处理顺序

```text
接收通知
  -> 验签
  -> 解析业务字段
  -> 幂等判断
  -> 必要时主动查询核验
  -> 更新本地状态
  -> 返回成功确认
```

## 幂等建议

| 通知类型 | 默认幂等 key | 状态更新原则 |
|----------|--------------|--------------|
| 分账方打款认证 | `login_name/alt_mch_no + auth_status` | 认证成功不得被旧的认证中覆盖 |
| 图片审核 | `alt_mch_no + 图片类型 + approve_status` | 审核通过后谨慎处理后续不通过通知，必要时主动查询 |
| 页面签约 | `alt_mch_no + 签约状态或签约流水` | 签约成功作为终态处理 |
| 手工结算 | `mch_order_no + order_status` | 已成功结算不得被处理中或旧失败覆盖 |

验签失败、字段不完整或本地落库失败时，不要返回成功确认。
