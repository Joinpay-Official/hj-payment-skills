# 分账方 `/allocFunds` 签名规则

本规则适用于分账方入网与结算接口，例如：

- `altmch.create`
- `altmch.modify`
- `altmch.query`
- `altMchPics.uploadPic`
- `altMchPics.modifyPic`
- `altMchPics.queryPicsInfo`
- `altMchSign.querySignContent`
- `altMchSign.sign`
- `altMchSign.getSignUrl`
- `altMchSign.querySignRecord`
- `altSettle.launch`
- `altSettle.get`
- `altSettle.getAutoSettle`
- `altAccount.get`

它不适用于聚合支付 `/tradeRt/*`。分账方入网 V1.4.2 明确 `altmch.create` 无 AES 加密；不要把二级商户 `/altFunds` 的字段名 `sec_key` 直接套入本接口。

## 公共参数

| 参数 | 说明 | 是否参与签名 |
|------|------|--------------|
| `method` | 方法名 | 是 |
| `version` | 接口版本；结算文档当前使用 `1.1` | 是 |
| `data` | 业务 JSON | 是 |
| `rand_str` | 32 位随机串 | 是 |
| `sign_type` | `1`=MD5，`21`=RSA | 是 |
| `mch_no` | 商户号 | 是 |
| `sign` | 签名值 | 否 |
| `aes_key` | V1.4.2 `altmch.create` 不需要；如其他返回或存量接口出现，签名时排除 | 否 |

分账方入网文档提到签名时排除 `sign`/`aes_key`。如果具体接口返回或请求中出现 `aes_key`，签名时也排除。

## 待签名串

1. 排除 `sign`，如存在 `aes_key` 也排除
2. 参数按 ASCII 字典序排序
3. 使用 `key=value` 形式拼接，字段间用 `&`

```text
data=<data JSON>&mch_no=<商户号>&method=<方法名>&rand_str=<随机串>&sign_type=<1或21>&version=<版本>
```

## MD5 签名

拼接规则：

```text
待签串&key=商户密钥
```

然后做 MD5 加密。

## RSA 签名

| 项 | 规则 |
|----|------|
| `sign_type` | `21` |
| 算法 | `MD5withRSA`，按 V1.4.2 文档 `RSAUtil.sign(signStr, secretKey, false)` 口径 |
| 编码 | UTF-8 |
| 请求签名私钥 | 商户 RSA 私钥 |
| 响应/通知验签公钥 | 汇聚平台 RSA 公钥 |
| 请求签名输出 | `base64(signatureBytes)`，即 V1.4.2 文档 `RSAUtil.sign(signStr, secretKey, false)` 的返回值 |
| 响应/通知验签输入 | 先 `HEX` 解码平台返回的 `sign` 得到 Base64 文本，再 Base64 解码为签名字节 |

注意：V1.4.1 及更早资料中可能出现 `sign_type=2` 和 `SHA1withRSA` 旧口径；V1.4.2 之后分账方接口以 `sign_type=21` 和 `MD5withRSA` 为准。

Java 请求签名口径：

```java
byte[] dataBytes = data.getBytes(StandardCharsets.UTF_8);
byte[] keyBytes = Base64.getDecoder().decode(mchPrivateKey);
Signature signature = Signature.getInstance("MD5withRSA");
signature.initSign(privateKey);
signature.update(dataBytes);
return Base64.getEncoder().encodeToString(signature.sign());
```

Java 响应/通知验签口径：

```java
byte[] dataBytes = data.getBytes(StandardCharsets.UTF_8);
byte[] signBytes = Base64.getDecoder().decode(hexToText(sign));
Signature signature = Signature.getInstance("MD5withRSA");
signature.initVerify(jpPublicKey);
signature.update(dataBytes);
return signature.verify(signBytes);
```

## 敏感字段加密

V1.4.2 文档明确“分账方添加无 AES 加密”，因此 `altmch.create` 示例不生成 `aes_key`，`legal_person`、`id_card_no`、`bank_account_name`、`bank_account_no` 也按明文参与 `data` 签名。

如果维护存量 V1.4.1/2.0 接入，可能仍会看到 `aes_key`、`AES/CBC/PKCS5Padding` 和 `AES key:IV` 规则；该存量口径不要套用到 V1.4.2 新接入示例。

## data 处理建议

文档要求 `data` 参与签名。实现时必须保证：

- 签名时使用的 `data` 和实际发送的 `data` 完全一致
- 签名后不得重新格式化或重新序列化 JSON
- 金额字段统一保留两位小数字符串
- 参数值避免包含 `=`、`|`、`%`、`<` 等特殊字符

## 排错优先级

| 现象 | 优先检查 |
|------|----------|
| 验签失败 | `sign_type` 是否与签名实现匹配（`1` 或 `21`） |
| 验签失败 | 是否按字典序拼 `key=value&key=value` |
| 验签失败 | `data` 签名原文和请求原文是否完全一致 |
| MD5 失败 | 是否漏掉 `&key=` + 商户密钥 |
| RSA 请求签名失败 | 是否错误使用了 `SHA1withRSA`、`SHA256withRSA` 或额外 HEX 包装 |
| RSA 验签失败 | 是否先 HEX 解码 `sign`，再 Base64 解码签名字节 |
| 回调验签失败 | 是否错误让 `sign` 或 `aes_key` 参与验签 |
