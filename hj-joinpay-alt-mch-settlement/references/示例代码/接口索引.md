# 分账方入网与结算示例代码索引

这些示例演示 `/allocFunds` JSON 协议的关键动作：紧凑 JSON、`key=value&key=value` 待签名串、MD5/RSA 双签名，以及 `altmch.create`、`altSettle.launch`、`altAccount.get` 三个主链路接口。示例不包含真实商户资料、密钥或生产可直接提交的完整入网字段。

| 语言 | 示例文件 | 说明 |
|------|----------|------|
| Java | [AltMchSettlementExample.java](Java/AltMchSettlementExample.java) | JDK 标准库实现，适合 Java 8+ 改造 |
| PHP | [alt_mch_settlement_example.php](PHP/alt_mch_settlement_example.php) | 使用 cURL 和 `md5()` |
| Python | [alt_mch_settlement_example.py](Python/alt_mch_settlement_example.py) | 使用 `requests` |
| Go | [alt_mch_settlement_example.go](Go/alt_mch_settlement_example.go) | 使用 Go 标准库 |

## 示例覆盖接口

| 接口 | method | 示例函数 | 说明 |
|------|--------|----------|------|
| 分账方添加 | `altmch.create` | `createAltMch` / `create_alt_mch` | 演示 V1.4.2 的 1.1 入网字段、结算账户字段和 `notify_url` |
| 手工结算 | `altSettle.launch` | `launchSettle` / `launch_settle` | 演示结算金额、结算订单号、服务费和结算回调 |
| 账户余额查询 | `altAccount.get` | `queryAccount` / `query_account` | 演示按 `alt_mch_no` 查询余额 |

## 使用前替换

| 占位符 | 说明 |
|--------|------|
| `YOUR_MERCHANT_NO` | 商户编号 `mch_no` |
| `YOUR_MERCHANT_KEY` | MD5 商户密钥，`sign_type=1` 时使用 |
| `MERCHANT_PRIVATE_KEY_PEM` | 商户 RSA 私钥，`sign_type=21` 时使用 |
| `JP_PUBLIC_KEY_PEM` / `jpPublicKeyPem` | 汇聚平台 RSA 公钥，验签响应或异步通知时使用 |
| `YOUR_CALLBACK_URL` | 入网、签约或结算异步通知地址 |
| `ALT_MCH_NO_PLACEHOLDER` | 分账方编号 |
| `BANK_CHANNEL_NO_PLACEHOLDER` | 对公账户联行号，企业对公打款认证需要 |

## 注意

1. 示例默认使用 `sign_type=1` 的 MD5 签名；将示例中的 `SIGN_TYPE/signType` 改为 `21` 后使用 V1.4.2 的 `MD5withRSA` 签名，签名值直接返回 Base64 文本。
2. `data` 一旦序列化并参与签名，请求发送时必须使用同一个字符串。
3. 示例中的 `altmch.create` 字段按 V1.4.2 核心字段补齐了主体、法人、联系人、结算规则和结算账户字段，版本号使用 `1.1`。
4. 手工结算前必须确认分账方已完成信息认证、图片审核和协议签约。
5. V1.4.2 分账方添加无 AES 加密，示例不生成 `aes_key`，也不加密 `legal_person`、`id_card_no`、`bank_account_name`、`bank_account_no`。
6. RSA 验签时，先对汇聚返回的 `sign` 做 HEX 解码得到 Base64 文本，再 Base64 解码得到签名字节；不要把请求签名的 Base64 输出也额外 HEX 包装。
